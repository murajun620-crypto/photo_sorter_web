# PhotoSorter Web — 写真をブラウザ内で整理

[アプリを開く](https://murajun620-crypto.github.io/photo_sorter_web/) · [ソースコード](https://github.com/murajun620-crypto/photo_sorter_web)

子供や友人の顔で JPEG・PNG を選別し、日付・イベント別に整理して出力する静的 Web アプリです。顔の比較、ボケ判定、撮影日時の読み取り、圧縮は、選んだ写真を使ってブラウザ内で実行します。写真や顔の特徴量をサーバーへアップロードする処理はありません。

ページ・ライブラリ・公開の顔モデルは配信元から読み込みます。モデルを含めて同じサイト内に同梱しており、利用時の外部 CDN やアカウント登録は不要です。顔の登録内容と解析結果はこのタブのメモリ内に保持し、ページを閉じると失われます。

写真フォルダを開くと、解析前から表示中の写真のサムネイルを順に作成します。表示ページを切り替えると、そのページの写真を読み込みます。

イベント名と日付の設定だけは、このブラウザの `localStorage` に保存します。写真や顔の特徴量は `localStorage` に保存しません。他の端末やブラウザへ自動同期する機能はありません。

## アプリの更新

画面上部に現在のバージョンを表示します。**更新確認**を押すと最新バージョンを確認でき、更新があれば **更新して再開** を選べます。

更新時は、写真・人物登録・分類結果・イベント・画面設定を、このブラウザ内の IndexedDB へ一時保存します。再読み込み後に作業を復元し、一時保存を削除します。保存容量の不足などで保存できない場合は更新を中止し、現在の作業を残します。復元に失敗した場合は一時保存を保持し、**復元を再試行**できます。写真の送信は行いません。

## 使い方

1. 整理する写真フォルダを選びます。JPEG・JPG・PNG とサブフォルダ内の写真が対象です。
2. 読み込んだ写真をクリックし、**この写真から人物を登録**を選びます。検出した顔の四角をクリックして、名前を入力します。同じ集合写真から複数人を続けて登録できます。左の **読み込んだ写真から登録**からも写真を選べます。
3. 必要に応じてイベント名と開始日・終了日を登録します。1日のイベントは開始日と終了日を同じ日にします。旅行などの複数日にわたるイベントも指定できます。
4. 写真を解析し、顔の一致・ボケ候補・日付を確認して出力対象を選びます。自動判定の結果は手動で調整できます。
5. 圧縮する場合は1枚あたりの上限容量を指定し、出力します。対応ブラウザでは選んだフォルダに直接保存でき、それ以外では ZIP をダウンロードして展開します。

顔が検出されない場合は **顔を囲んで指定**を選び、目・鼻・口を含む顔全体をドラッグして囲みます。囲んだ範囲で1人の顔が確認できた場合に登録します。複数人が入った範囲や顔が確認できない範囲では、囲み直しを案内します。

「登録先の人物」で既存の人物を選ぶと、同じ人に角度・表情の違う参照写真を追加できます。「＋ 新しい人物を登録」で別の人を登録できます。まず同じ撮影時期の正面・斜め・表情の異なる顔を3〜5枚、目安として登録してください。解析済みの候補は登録例に合わせて更新でき、未解析の写真は全体解析で処理します。

## OK／NGで人物判定を調整

1. 左の人物一覧で対象を選び、**OK／NGで判定を調整**を押します。最初は全体から最大12枚を試し判定します。
2. オレンジの枠の顔について、**OK・本人**、**NG・別人**、**わからない・次へ**を選びます。集合写真も顔ごとに確認します。
3. OKは本人の追加参照、NGは本人ではない例に使います。解析済みの写真は保存した特徴量から再判定し、残りの写真にも全体解析時に適用します。
4. 必要なだけ確認したら終了して、**写真を解析**で全体を処理します。再度調整すると、未回答の候補や次の試し判定を確認できます。

回答を訂正する場合は **回答済みのOK／NGを見直す** にチェックし、調整を開き直してください。訂正時はその回答で追加した例だけを入れ替え、元々手動登録した顔写真は維持します。

1つの顔を自動で複数人物へ割り当てません。上位の人物候補が近い顔、しきい値付近の顔、NG例にも近い顔や顔未検出の写真は **要確認** にまとめます。要確認の候補名は確定した人物と区別し、勝手にその人物フォルダへ振り分けません。人が写真全体へ指定した人物は自動推定より優先します。

OK／NGはこのタブ内の参照例と判定に使います。写真や顔の特徴量を外部で学習させる通信はなく、タブを閉じると登録内容とともに失われます。**更新して再開**では、OK／NGとボケの基準例も一時保存して引き継ぎます。元の顔認識モデル自体を再学習する機能ではありません。

## 人物ごとの出力

初期設定では人物ごとのフォルダに出力します。集合写真で複数の登録人物が一致した場合は、それぞれの人物フォルダへ同じ写真をコピーします。友人ごとに渡したい写真を分ける用途に使えます。

まとめて出力する場合は、「選んだ写真をひとつにまとめる」または「登録した全員が写る写真をまとめる」という条件も使えます。人物の一致は機械による推定です。渡す前に写真と出力先を確認してください。

## 日付・イベント

写真の EXIF に記録された撮影日時を優先します。撮影日時を取得できないファイルは、ファイルの更新日時を代用し、そのことが分かるように表示します。更新日時はコピーや編集で変わることがあるため、撮影日とは限りません。

人物別の出力では、人物フォルダの中をイベント、日付の順に整理し、元のサブフォルダ名も引き継ぎます。開始日と終了日の両方を含む期間をイベントとして扱います。イベントの期間が重なる設定は受け付けません。同じイベントの期間や名前は編集できます。イベントに含まれない写真は、日付フォルダへ整理します。

```text
出力フォルダ/
  はる/
    2026-08-10_2026-08-13_家族旅行/
      2026-08-10/
        元のサブフォルダ/
          IMG_1234.jpg
  りく/
    2026-08-10_2026-08-13_家族旅行/
      2026-08-10/
        元のサブフォルダ/
          IMG_1234.jpg
```

この例では、同じ集合写真を2人のフォルダへ保存しています。圧縮する場合は元の名前に `.jpg` を加えます（例：`IMG_1234.png.jpg`）。人物が見つからない写真を手動で出力対象にした場合は、「人物未分類」フォルダに入ります。

## ボケた写真の退避と復元

ボケ候補の自動除外は初期状態でOFFです。輪郭の強さによる参考値だけで、鮮明な写真を自動で除外することを避けます。

写真を開き、「ボケ判定の基準例」で **この写真は鮮明** と **この写真はボケている** をそれぞれ3枚以上指定します。同じ撮影日、同じ評価対象（顔／写真全体）ごとに、両者の例を分けられる場合だけ **調整した基準を適用**できます。分けられない条件や基準のない写真は、自動除外せず要確認に残します。

これは指定した例からの基準調整で、一般的なピント判定を保証するものではありません。顔の大きさ・背景の模様・ノイズなどで値は変わるため、候補を確認してください。基準を無効にしたり例が重なった場合は、自動除外を解除し、人が明示して外した写真はその選択を維持します。「現在の設定で選び直す」は手動の出力選択をリセットして自動で選び直します。

Web アプリから OS のごみ箱は使えません。書き込み権限を許可した対応ブラウザでは、確認して選んだ元写真を、写真フォルダ内の `_PhotoSorter_退避` フォルダへ退避できます。退避先のコピーを検証した後に元の場所から取り除く方式です。退避した写真は復元操作で元の場所に戻せます。ごみ箱や完全削除とは異なります。

書き込み機能に対応していないブラウザや、読み取り専用のフォルダ選択では元写真を変更できません。ボケ候補を出力から外し、元写真の整理はファイル管理アプリで行ってください。

## 指定サイズへの圧縮

上限は**1枚ごとのファイルサイズ**です。1 KB = 1,000 bytes、1 MB = 1,000,000 bytes として扱います。指定値ちょうどではなく、指定値以下になるように JPEG の品質を調整します。必要な場合に解像度を下げる設定も利用できます。

- JPEG 圧縮では PNG も JPEG になり、透明部分は白背景になります。
- 圧縮時は EXIF などの元のメタデータを出力へ引き継ぎません。日付による分類は、圧縮前に読み取った日時を使います。
- 画質や解像度を調整しても指定容量に収まらない写真は、容量超過のまま保存せずエラーとして扱います。
- 圧縮しない場合は元のファイルをコピーします。

## ブラウザの違い

| 操作 | Chrome・Edge の対応環境 | Firefox・Safariなど |
| --- | --- | --- |
| フォルダから写真を選んで解析 | 対応 | フォルダ選択が可能な環境で対応 |
| フォルダへ直接保存 | ブラウザの書き込み許可が必要 | ZIP 出力を利用 |
| 元写真の退避・復元 | フォルダの読み書き許可が必要 | 利用不可 |

フォルダへの直接アクセスには HTTPS または localhost が必要です。実際の機能は、そのブラウザで利用できる API を判定して切り替えます。対応状況は [MDN の showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker) も参照してください。ZIP はブラウザのメモリを使うため、大量の写真は何回かに分けると扱いやすくなります。

ZIPは合計700 MBまでを扱います。大量の写真にはフォルダへの直接出力を使ってください。1枚あたり6,400万画素・長辺16,384pxを超える画像は、ブラウザのメモリ制約のため対象外です。

## GitHub Pages で公開

このフォルダはビルド不要です。`index.html`、アプリの JavaScript・CSS、`vendor/`、`models/`、`licenses/`、`.nojekyll` を含むフォルダ全体をリポジトリへ置いてください。

GitHub リポジトリの **Settings → Pages** で、公開元のブランチとルートディレクトリを選ぶと配信できます。手順は [GitHub の公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) を参照してください。相対パスで読み込むため、`https://ユーザー名.github.io/リポジトリ名/` のようなプロジェクトサイトでも使えます。GitHub Pages へ置くのはアプリと公開モデルだけです。個人の写真をリポジトリに追加する必要はありません。

## ローカルで開発・確認

`file://` で HTML を直接開くとモデルの読み込みやフォルダ API が動作しない場合があります。静的 HTTP サーバーを使ってください。Python がある環境では、このフォルダで次を実行できます。

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

ブラウザで `http://localhost:8765/` を開きます。Node.js、npm install、サーバー側の写真処理は不要です。

## 判定の限界とライセンス

顔の値は本人である確率ではなく、特徴量の距離です。横顔、隠れた顔、小さな顔、成長による変化や似た顔では、見落とし・誤一致があります。実際のお子様の写真で精度を検証したものではありません。

使用モデル・ライブラリの出典とライセンスは [LICENSES.md](LICENSES.md)、同梱ファイルのハッシュは [asset-lock.json](asset-lock.json) にあります。
